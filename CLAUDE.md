# CS2 Stata — контекст для Claude

Статический сайт (GitHub Pages, репозиторий `msnka-smr/LLstat`, живой адрес
`https://msnka-smr.github.io/LLstat/`), который считает статистику и рейтинг
CS2-матчей команды друзей по данным API cybershoke.net. Никакого бэкенда —
только Node-скрипты, которые генерируют `docs/data/stats.json`, и ванильный
JS/HTML/CSS на странице, без сборки и npm-зависимостей в браузере.

Полное историческое ТЗ и обоснование архитектурных решений — в SPEC.md.

## Как это работает

```
data/matches/<id_lobby>.json   сырые ответы cybershoke lobbys/info, по файлу на лобби
        ↓ scripts/collect.mjs (тянет новые матчи по куке или вручную по ссылкам)
        ↓ scripts/build.mjs   (агрегация, рейтинги, пороги квалификации)
docs/data/stats.json           всё, что читает страница (allTime, sessions — все
                               сессии от новой к старой, ratingHistory — рейтинг
                               каждого игрока после каждой сессии, records — 15
                               рекордов, maps; у каждой сессии есть recap — топ-3,
                               рост и просадка рейтинга за вечер; строятся в
                               scripts/lib/sessionsOutput.mjs, ratingHistory.mjs,
                               records.mjs, recap.mjs)
docs/index.html                сама страница (fetch stats.json → рендер)
```

- `npm run update` — скачать новые матчи по куке из `.env` (`CYBERSHOKE_COOKIE`),
  пересобрать, закоммитить и запушить одной командой.
- `npm run add -- <ссылки на матчи cybershoke.net>` — то же самое, но без
  авторизации, по явным ссылкам (`npm run add -- --file links.txt` для списка).
- `npm run build` — только пересобрать `docs/data/stats.json` из уже
  скачанных `data/matches/*.json`.
- `npm test` — юнит-тесты (`node --test`), сейчас 128 тестов, все проходят.
- `update-stats.bat` (ярлык «Обновить статистику CS2» на рабочем столе) —
  окно «вставил ссылки → Enter» для пользователя без Claude. Внутри
  `scripts/update-stats.ps1` → `npm run add -- --basic-if-pending --file …`:
  демки не ждём, статистика из лобби (решение пользователя от 2026-10-02).
  `update.mjs` не пересобирает и не коммитит, если в `data/` ничего не
  изменилось (иначе каждый запуск давал бы коммит из-за `generatedAt`).
- `.github/workflows/update-stats.yml` — то же самое кнопкой на GitHub
  (Actions → «Обновить статистику» → Run workflow, ссылки через пробел).
  Первым шагом проверяет, пускает ли cybershoke/Cloudflare запросы с
  раннеров GitHub. Так как коммиты теперь бывают и с GitHub, `update.mjs`
  начинает с `git pull --rebase --autostash`.

**Аватарки**: cybershoke запоминает аватарку игрока один раз и не обновляет
(у moloko в матчах с июня одна и та же, в Steam уже другая). Поэтому
`update.mjs` после `collect` запускает `scripts/refresh-avatars.mjs`: он берёт
`avatarFull` из `steamcommunity.com/profiles/<id>?xml=1` (без ключа API) и пишет
в `data/players.json` поле `steamAvatarUrl`; `build.mjs` предпочитает его
`avatarUrl` из матчей. Сбой Steam или закрытый профиль не роняют обновление,
остаётся прошлое значение. Логика и тесты — `scripts/lib/steamAvatar.mjs`.
Ручной `npm run build` без новых матчей гасит одноразовое уведомление
`qualificationDrop` (оно живёт только до следующей сборки).

**Важно про пуш**: песочница агента не может достучаться до `github.com`
(сетевой блок на уровне провайдера/окружения, не самого агента — подтверждено
даже с отключённым сэндбоксингом). `api.github.com` и
`objects.githubusercontent.com` доступны, сам `github.com`/Pages — нет.
Поэтому Claude коммитит локально, а `git push` всегда выполняет сам
пользователь в своём терминале.

## Данные и их проблемы (уже исправлено, но важно помнить)

cybershoke отдаёт два уровня данных на лобби: полный разбор демки
(`match_more_stats.stats`, есть не всегда) и лобби-статы
(`match_stats.base` + `data.players[].match_stats.live`, есть почти всегда).

**Жёсткое правило: K/D всегда берётся из лобби (`match_stats.live`), не из
демо-разбора.** На реальных матчах демо-парсер cybershoke иногда безвозвратно
теряет чьи-то смерти (найдено на живом матче: 9/0 в демке против настоящих
9/12 на странице матча) — подтверждено скриншотами, не предположением.
Команда/победитель/счёт по-прежнему берутся из демо-статов (`stats`), с
поправкой на баг ниже.

**Фантомный ножевой раунд**: cybershoke иногда засчитывает раунд выбора
стороны (ножевой) как настоящий раунд №1, добавляя +1 очко победившей его
команде и +1 к `totalRounds`. Признак — все килы раунда №1 оружием `"Knife"`.
`detectPhantomKnifeRound()` в `scripts/lib/normalize.mjs` вычищает это из
счёта, `totalRounds` и индивидуальных смертей жертв этого раунда.

Все эти фиксы покрыты регрессионными тестами в `test/normalize.test.mjs`
с комментариями, ссылающимися на конкретные id матчей, где баг был найден.

## Рейтинг

Два независимых рейтинга, оба на одной шкале **1–1500** (см.
`docs/rating-info.html` — открытая игрокам документация, обязательно
синхронизировать при любом изменении формул/весов/тиров).

**Сессионный** (`scripts/lib/sessionRating.mjs`) — статический, считается
заново по картам одного вечера:
```
score  = K/D_ratio × 0.6 + (avg_K−D_за_карту / 10) × 0.3 + winRate × 0.1
рейтинг = 500 + (score − 0.65) × 350   // 0.65 — score среднего игрока
```

**За всё время** (`scripts/lib/allTimeRating.mjs`) — ELO-подобный, реплеит
все карты игрока в хронологическом порядке от базы 500:
```
bonus  = (matchKD − 1.0) × 0.8   // относительно фиксированного 1.0, НЕ своего среднего
delta  = K_coef × (result × 0.2 + bonus)   // result = ±1
K_coef = 8 для первых 5 карт игрока, дальше 5
```
Раньше `bonus` считался относительно собственного среднего K/D игрока — это
оказалось некорректно: стабильный игрок (хорошего или плохого уровня) в
среднем получает бонус около нуля независимо от абсолютного уровня, и в итоге
рейтинг предопределялся почти исключительно винрейтом состава. Фиксированная
база 1.0 — осознанное решение, проверенное на реальных данных
(MrDrolik/moloko, Пикулинни/Седой).

Оба MAX_RATING/веса менялись по ходу калибровки несколько раз по прямому
запросу — если меняешь снова, обязательно: пересчитать `docs/data/stats.json`
(`npm run build`), проверить, что порядок игроков в сессиях не переворачивается
неожиданно, и обновить `docs/rating-info.html` (формулы + тиры + примеры).

## Telegram-бот обновления статистики

`bot/` — Cloudflare Worker. Владелец присылает боту ссылки на лобби, воркер
(`bot/src/worker.mjs`) проверяет секретный заголовок и Telegram ID и запускает
`.github/workflows/update-stats.yml` через `workflow_dispatch`; ссылки
разбирает `bot/src/links.mjs`. Об итоге сообщает последний шаг самого workflow
(секреты репозитория `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). Настройка и
деплой — `bot/README.md`, дизайн — `specs/2026-10-19-telegram-bot-design.md`.
Секреты воркера живут только в Cloudflare (`wrangler secret put`), в репозиторий
не попадают. Изменение формата ввода workflow (`inputs.links`) требует правки
воркера.
Коммит бота через `GITHUB_TOKEN` не запускает деплой Pages сам, поэтому workflow
после обновления явно просит сборку (`POST /pages/builds`, нужно `pages: write`).
Если запрос не прошёл, в Telegram приходит предупреждение.

## Устройство `docs/index.html`

Одностраничник на ванильном JS (без React/сборки), пять вкладок («За всё
время», «Сессии», «Карты», «Выбор составов», «Рекорды» — «Рекорды» последняя,
по решению пользователя; на экране ≤ 520px вкладки идут двумя рядами на всю
ширину без пустоты — сетка из 6 колонок, 3 вкладки по 2 колонки и 2 по 3;
в одну строку пять вкладок ~430px не помещаются), переключатель
хранится в `localStorage` (`llstat:selectedTab`), fetch данных идёт с
`{ cache: "no-store" }` — GitHub Pages отдаёт `stats.json` с
`Cache-Control: max-age=600`, без этого обычный F5 полчаса показывал бы
устаревшие цифры.

- **«За всё время»** / **«Сессии»** — таблица игроков, сортировка
  по клику на заголовок (десктоп) или через select+кнопку-направление
  (мобильный, `.mobile-sort`, т.к. колонки Карт/K/D/K/D скрыты на узком
  экране и переезжают строкой под именем — `.player-meta`). Абсолютные
  цветовые тиры (`SESSION_TIERS`/`ALLTIME_TIERS`), не относительные к
  среднему по лиге.
  Вкладка «Сессии» показывает выбранную сессию: список над таблицей (по
  умолчанию и после перезагрузки — последняя), состояние в `state.sessionId`,
  доступ через `currentSession()`, подпись — `sessionLabel()` (дубль в тот же
  день — «(№2)»). Внутренний id вкладки по-прежнему `lastSession` ради
  сохранённого в `localStorage` выбора. Пока крутится колесо, смена сессии
  блокируется. Бейдж `ratingDelta` на «За всё время» — всегда за последнюю
  сессию (`sessions[0]`).
  **«Итоги вечера»** (`renderRecapPanel`, `drawRecapCard`, `renderRecapCard`) —
  кнопка рядом со списком сессий (есть, только если у сессии есть `recap`);
  раскрывает карточку-картинку на canvas 1080px (двухпроходный расчёт высоты:
  замер, затем рисование; цвета и шрифт из CSS-переменных): MVP, топ-3, «Больше
  всего вырос»/«просел» (рейтинг «за всё время» за вечер), карты (до 8, остальное
  «и ещё N»), «Шутка вечера» из `EXCUSES`. Кнопки: «Скачать PNG», «Копировать»
  (буфер обмена, при отказе — сообщение скачать), «Другая фраза». Без аватарок
  Steam: кросс-доменные картинки «пачкают» canvas и ломают `toBlob`. Шрифт
  карточки — шрифт страницы (`recapFontFamily`, с body), отрицательные числа на
  ней со знаком «−» (`recapMinus`), счёт везде «победитель первым» (в шапке
  сессии, на карточке, в рекордах). Шапка сессии не пересобирается, если не
  менялись вкладка/сессия/состояние панели (ключ `el.dataset.key` в
  `renderSessionHeader`), иначе любая перерисовка страницы пересоздавала бы
  карточку и стирала сообщение «Скопировано». Тон мягкий
  («просел»); блок «Рекорды вечера» сознательно не делали (на большинстве вечеров
  был бы пуст). MVP считается среди ВСЕХ игроков вечера (не только
  квалифицированных). Текстовая версия карточки — `aria-label` у canvas.
- **«Динамика рейтинга»** (`renderHistorySection`/`drawHistChart`) — блок под
  таблицей «За всё время»: линейный график рейтинга по сессиям, до 6 игроков
  для сравнения (по умолчанию топ-3 квалифицированных, чипы-легенда), встроенный
  SVG на ванильном JS, подсказка по наведению/тапу/стрелкам, сворачиваемая
  таблица значений. Ось X — сессии, а не карты (решение пользователя
  2026-10-13: по картам график шумел бы при росте числа карт). Игрок пропустил
  сессию — линия идёт ровно, маркеры только в сыгранных сессиях (кто играл —
  из `sessions[].players`). Подписи сессий (`histLabels`): «ДД.ММ», при данных
  из нескольких лет у всех добавляется год («ДД.ММ.ГГ»), 2-я и далее сессия
  дня — суффикс « №N»; в шапке таблицы полная дата лежит в `title`. Цвета линий — `HIST_COLORS`, 6 слотов тёмной палитры
  dataviz, проверенные `validate_palette.js --mode dark --surface "#1b1e26"`:
  не менять без повторной проверки.
- **Колесо фортуны ВРЕМЕННО УБРАНО с сайта (2026-10-29)**, код упакован в
  `modules/wheel/` (README с шагами возврата; по просьбе «верни рулетку» —
  вернуть по нему). Ниже — описание, как оно работало. Оно (`renderWheelSection`) было только на вкладке «Сессии» (для
  выбранной сессии), чисто ради фана. 6 категорий, 2 из них — «Тащер вечера»/«Посмотрю
  стримы...» — детерминированные (лучший/худший по рейтингу сессии), 4 —
  честный рандом. Категория не повторяется два раза подряд.
- «Оправдалка» (`renderExcuseSection`, массив `EXCUSES`) — тоже только на
  «Сессиях», под колесом (от выбранной сессии не зависит), чисто ради фана. Облако мемных отмазок
  CS2-игроков, без привязки к игроку (решение 2026-10-13); кнопка по очереди
  зажигает 3–5 случайных фраз с ✅. Облако — 3D-сфера
  на ванильном JS (`tickExcuseSphere`, спираль Фибоначчи, авто-вращение,
  перетаскивание с инерцией; при `prefers-reduced-motion` без авто-вращения),
  цвета только из переменных сайта. Чтобы добавить фразу — дописать в `EXCUSES`
  (длинные переносятся по `max-width`, сфера подстраивается сама).
- **«Рекорды»** (`renderRecordsSection`, `noTableTab`) — 15 рекордов в четырёх
  группах: «Личные рекорды», «Серии», «Матчи», «Бывает с каждым»; у каждого
  топ-3 с картой, датой и ссылкой на матч. Название последней группы и мягкие
  названия её рекордов («Трудная карта», «Карта не задалась», «Горячая точка»,
  «Полоса неудач») — решение пользователя 2026-10-13, не заменять на «доску
  позора» и т.п. Один игрок — одно место в топе (его лучший результат);
  равные результаты делят место (`place`), не поместившиеся в топ-3 — в
  `more` («и ещё N с таким же результатом»); исключение — «Железная
  посещаемость» (решение пользователя 2026-10-22): там показаны ВСЕ, кто делит
  1-е место, без потолка (`allLeaders` в `pickTop`); ничья и `won: null` не считаются
  ни победой, ни поражением;
  пороги `MIN_KILLS_FOR_KD = 15`, `MIN_DEATHS_FOR_KD = 10`, серия не короче 2
  (`scripts/lib/records.mjs`); в серии «K/D не ниже 1.0» карта 0/0 игнорируется
  (не рвёт и не продлевает), «Железная посещаемость» считает сессии, а не
  «вечера» (две сессии в один день — две). Чтобы добавить рекорд — запись в `computeRecords`
  (+ тест) и ветка в `recordValueText` на странице.
- **«Выбор составов»** (`renderDraftSection`) — выбрать ровно 10 игроков (из
  вообще всех, кто хоть раз сыграл карту), система делит на 5×5, минимизируя
  разницу по рейтингу (30%), суммарной K-D (30%) и K/D (40%), каждый
  нормирован к разбросу внутри выбранной десятки. Перебор всех 126 уникальных
  разбиений (`C(10,5)/2`) — точный оптимум, без эвристик. Не больше 2
  сгенерированных вариантов на конкретный набор из 10 (лимит в `localStorage`
  по ключу из отсортированных steamid64, переживает перезагрузку страницы);
  переключение между уже показанными вариантами — бесплатное.
  **Гости** (игроки со стороны, решение 2026-10-13): минимум 4 из списка, остальные
  до десяти — гости с именем до 40 символов (пусто → «Гость N») и рейтингом «на
  глаз» 1–1500 (по умолчанию 500). Всего всегда 10 (5×5). У гостей нет K/D и
  K-D, их оцениваем линейной регрессией по рейтингу на всех игроках «за всё
  время» (`draftEstimator`), дальше формула баланса та же для всех десяти;
  оценённые числа на экран не выводятся, только рейтинг и пометка «гость».
  Гости не сохраняются; в ключ лимита «2 варианта» входят имя и рейтинг гостя.

## Тестирование изменений в `docs/index.html`

В песочнице недоступны внешние CDN и сам GitHub, поэтому проверка идёт через
локальный HTTP-сервер + Playwright, управляющий локальным Microsoft Edge
пользователя (`chromium.launch({ channel: "msedge" })` — публичный Chromium
Playwright недостижим из песочницы, а Edge уже стоит на машине пользователя):

```bash
cd docs && python -m http.server 8801
# в отдельном скрипте на node: playwright.chromium.launch({channel:"msedge"}),
# page.goto("http://localhost:8801/index.html"), скриншоты, проверка console errors
```
Всегда проверять и десктоп (1280px), и мобильный вьюпорт (375px, без
горизонтального скролла) перед коммитом.
