# Рекорды и зал славы — дизайн

Дата: 2026-10-13. Подпроект 3 из 4 (архив сессий ✅ → история рейтинга ✅ → **рекорды** → «Итоги вечера»).
Решения по ходу обсуждения с пользователем; `specs/` лежит вне `docs/`, чтобы не публиковаться на Pages.

## Цель

Новая вкладка «Рекорды»: лучшие (и забавные «не повезло») результаты группы за всё время, с привязкой к конкретной карте и ссылкой на матч.

## Принятые решения

- Место: отдельная вкладка «Рекорды» (id `records`), пять вкладок вместо четырёх; порядок — За всё время, Сессии, Карты, Выбор составов, **Рекорды** (последняя, после «Выбора составов» — уточнение пользователя).
- Группы: А (личные за карту), Б (серии), В (матчи), Д (мягкий антирейтинг), по 3–5 рекордов в группе; группа Г («вечера») не делается — частично видна на вкладке «Сессии».
- Название группы Д — **«Бывает с каждым»** (пользователь просил безобидное, не дизморалящее название; рекорды внутри названы мягко).
- Топ-3 у каждого рекорда.

## Рекорды (15)

Группа А — «Личные рекорды» (за одну карту; от игрока берётся его лучший результат, один игрок — одно место в топе):
1. `most-kills` — «Больше всего убийств за карту».
2. `best-kd-diff` — «Лучшая разница K-D за карту».
3. `best-kd` — «Лучший K/D за карту» (только карты с ≥ `MIN_KILLS_FOR_KD = 15` убийств).
4. `carry-in-loss` — «Тащил в проигрыше»: лучшая разница K-D на карте, которую команда игрока проиграла.

Группа Б — «Серии» (по картам игрока в хронологическом порядке; не сыгранные игроком карты серию не прерывают; один игрок — одно место):
5. `win-streak` — «Серия побед подряд».
6. `kd-streak` — «Серия карт подряд с K/D не ниже 1.0».
7. `attendance-streak` — «Железная посещаемость»: сколько сессий подряд игрок приходил (подпись «сессий подряд», а не «вечеров»: две сессии в один день считаются двумя); пропущенная сессия рвёт серию.

Группа В — «Матчи» (по картам, не по игрокам):
8. `biggest-win` — «Самый крупный разгром» (наибольшая разница счёта).
9. `closest-match` — «Самый упорный матч» (наименьшая разница счёта; при равенстве — больше раундов).
10. `longest-map` — «Самая долгая карта» (больше всего раундов).
11. `shortest-map` — «Самая короткая карта» (меньше всего раундов).

Группа Д — «Бывает с каждым» (один игрок — одно место):
12. `worst-kd-diff` — «Трудная карта»: худшая разница K-D за карту.
13. `worst-kd` — «Карта не задалась (наименьший K/D)»: самый низкий K/D за карту (только карты с ≥ `MIN_DEATHS_FOR_KD = 10` смертей).
14. `most-deaths` — «Горячая точка»: больше всего смертей за карту.
15. `loss-streak` — «Полоса неудач»: серия поражений подряд.

Правила:
- Пороги `MIN_KILLS_FOR_KD` и `MIN_DEATHS_FOR_KD` — константы в `scripts/lib/records.mjs`.
- Равные значения: выше тот, кто достиг результата раньше (по `playedAt`, затем стабильно по `mapId`+`steamid64`), **но место у равных общее** (1, 1, 1 / 1, 2, 2): в записи есть `place`, а у рекорда — `more`: сколько не поместившихся в топ-3 игроков делят результат с последним показанным («и ещё N с таким же результатом»). Уточнено после ревью: на реальных данных семь игроков имели одинаковую посещаемость, и показ трёх «случайных» выглядел несправедливо.
- Ничья (равный счёт) и неизвестный победитель (`won: null`) — не победа и не поражение: не входят в «Тащил в проигрыше», рвут серии побед и поражений.
- «Трудная карта» — только отрицательная разница K-D, «Тащил в проигрыше» — только положительная (плюсовой результат не должен попадать в «неудачи» и наоборот).
- `maps` и `sessions` должны идти от старой к новой (так отдаёт `build.mjs`); модуль сам не сортирует.
- Берутся все карты и все игроки из того же пула, что и «За всё время» (включая неквалифицированных).
- Если записей для рекорда нет (никто не набрал порог) — `top: []`.

## Данные (`scripts/build.mjs` → `docs/data/stats.json`)

Новое поле верхнего уровня `records` (остальные поля не меняются):

```
records: [
  { id, group, title, hint, top: [ entry, entry, entry ], more }, …   // more — сколько ещё игроков делят результат с последним показанным
]
```

`group` — одна из `personal | streaks | matches | oops` (последняя — «Бывает с каждым»). `hint` — короткая подпись («минимум 15 убийств», «подряд, по картам игрока»).

Записи `entry`:
- личный рекорд: `{ steamid64, value, k, d, map, playedAt, url }` (`value` — убийства / разница K-D / K/D / смерти соответственно, `url` — `https://cybershoke.net/match/<lobbyId>`);
- серия: `{ steamid64, value, from, to }` (`from`/`to` — `playedAt` первой и последней карты серии; у `attendance-streak` — `firstPlayedAt` первой и последней сессии серии);
- матч: `{ map, score: [a, b], rounds, playedAt, url }`.

Логика — чистый модуль `scripts/lib/records.mjs` (`computeRecords(maps, sessions)` → массив рекордов), `build.mjs` лишь вызывает его на `sortedMaps` и `sessions`. Имена и аватарки на странице берутся из `allTime.players` по `steamid64`.

## Страница (`docs/index.html`)

- Вкладка «Рекорды» (`data-tab="records"`, добавляется в `VALID_TABS`); таблица и «Выбор составов»/график на этой вкладке не показываются.
- Четыре раздела с заголовками «Личные рекорды», «Серии», «Матчи», «Бывает с каждым»; в каждом сетка карточек: название рекорда, подсказка (`hint`), до трёх строк топа (место, аватарка и имя либо карта и счёт, значение крупно, контекст мелко — карта, дата, ссылка «матч» / период серии).
- Сетка: 1 колонка на телефоне, 2–3 на десктопе. Только переменные сайта; раздел «Бывает с каждым» оформляется приглушённо, без красного.
- Нет рекордов в карточке — «Пока нет». Нет `records` в данных — «Рекордов пока нет.»
- Все данные в DOM (имена, карты) — через `textContent`; ссылки — `rel="noopener"`, `target="_blank"`.

## Проверка

- Юнит-тесты `records.mjs`: пороги K/D, один игрок — одно место, правило равенства, серии (пропущенные карты не рвут, разрыв по поражению/ничьей), посещаемость (пропущенный вечер рвёт), матчи (разгром, упорный, длиннее/короче), пустой вход.
- Сверка на реальных данных: вывод топ-3 всех рекордов для пользователя.
- Браузер (Edge через Playwright), 1280px и 375px: вкладка открывается, 15 карточек, не более 3 строк, ссылки верные, нет горизонтального скролла и ошибок, имя с HTML не превращается в разметку, вкладка сохраняется в `localStorage`; остальные вкладки не сломаны.
- `npm test` остаётся зелёным (на момент спеки — 72 теста), CLAUDE.md обновляется.
