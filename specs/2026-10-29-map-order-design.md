# MatchDay: порядок карт и составы на вечер — дизайн

Дата: 2026-10-29. `specs/` лежит вне `docs/`, чтобы не публиковаться на Pages.
Решения по ходу обсуждения с владельцем проекта.

## Зачем

Сейчас порядок карт на вечер один человек выбирает «на словах» и объявляет, а составы
каждый раз приходится пересказывать. Хотим, чтобы сайт определял случайный порядок карт,
владелец мог подправить составы, и всё это закреплялось на отдельной вкладке-витрине
**MatchDay**. В день сессии любой, кто откроет сайт, видит одно и то же: дату, составы и
карты в нужном порядке. Должно выглядеть красиво, а не списком.

## Цели

- Новая вкладка **MatchDay** («витрина вечера»), видна всем посетителям сайта.
  Порядок вкладок (решение владельца): «За всё время», «Сессии», «Выбор составов»,
  **MatchDay**, «Карты», «Рекорды». Раньше «Карты» шли третьими, теперь переезжают после
  MatchDay.
- MatchDay показывает сверху дату сессии, под ней две команды, ниже «Маршрут вечера»
  (карты в порядке игры). Каждую часть закрепляет владелец своей командой боту.
- На вкладке «Выбор составов» (рабочее место владельца) появляется:
  1. Правка выбранного варианта состава: поменять игроков местами между командами
     (если решили сами что-то перетасовать), с живым пересчётом среднего рейтинга команд.
  2. Блок «Порядок карт» с кнопкой **«Определить порядок карт»** (случайный порядок
     ровно 7 карт текущего пула).
  3. Для каждой части кнопка «Копировать команду» (текст для бота) и «Открыть бота».
- Закрепить на витрине можно только через Telegram-бота владельца: публичный сайт сам
  ничего в репозиторий не пишет.
- Карты пула: Mirage, Dust II, Inferno, Nuke, Ancient, Anubis, Cache (ключи `de_mirage`,
  `de_dust2`, `de_inferno`, `de_nuke`, `de_ancient`, `de_anubis`, `de_cache`).
- «Маршрут вечера» — вертикальная дорожка: пунктирная линия, кружки шагов 1–7, плашка
  каждой карты с её фоновой картинкой и названием (выбранный владельцем вариант «C» из
  макетов).
- Дата ближайшей сессии указывается владельцем в командах (идея владельца 2026-10-29) и
  показана на MatchDay крупно, например «Пятница, 31 октября».

## Не цели

- Отметки «сыграно ✓» на дорожке (владелец: пока не нужно, возможно позже).
- История прошлых вечеров: хранится только последнее закреплённое, новое заменяет старое.
- Права писать в репозиторий у сайта.
- Менять пул карт с сайта или ботом (пул — 7 карт, зашит в код).
- Пересчёт или правка самого алгоритма деления на команды: меняется только возможность
  вручную править готовый результат, формулы баланса остаются как есть.

## Решения владельца

- Составы и порядок карт закрепляются **разными командами** боту (не одной).
- Вариант состава (из двух предлагаемых) можно править вручную перед закреплением: менять
  игроков местами между командами.
- Закрепляет владелец через того же Telegram-бота, что обновляет статистику.
- Всегда 7 карт (играют 5–7, но показываем все семь).
- Дата сессии вводится **с годом**: `ДД.ММ.ГГГГ`.
- Название вкладки — «MatchDay», кнопка — «Определить порядок карт», маршрут — вариант C.

## Как устроено

```
«Выбор составов»: делим 5×5 → выбираем вариант → правим (меняем игроков местами)
      → «Копировать команду» даёт  /teams 31.10.2026 …   (формат — см. ниже)
«Выбор составов»: «Определить порядок карт» → 7 плашек (черновик, только у вас на экране)
      → «Копировать команду» даёт  /maps 31.10.2026 mirage nuke anubis inferno ancient dust2 cache
Вы → Telegram-бот (проверка Telegram ID, как сейчас) → GitHub API (workflow_dispatch)
   → workflow set-matchday.yml → обновляет docs/data/matchday.json → коммит → сборка Pages
Вы ← Telegram: «Составы закреплены» / «Порядок карт закреплён»
Любой посетитель: вкладка MatchDay → fetch data/matchday.json → дата, команды, дорожка
```

### Данные: `docs/data/matchday.json`

Один файл. **Дата сессии одна на весь MatchDay** (решение владельца 2026-10-29): составы
и карты можно закреплять в разные дни, но играть будем в один назначенный день. У каждой
части свой `savedAt` (когда закреплено), а дата общая:

```json
{
  "sessionDate": "2026-10-31",
  "maps": {
    "order": ["de_mirage", "de_nuke", "de_anubis", "de_inferno", "de_ancient", "de_dust2", "de_cache"],
    "savedAt": "2026-10-29T16:40:00Z"
  },
  "teams": {
    "teamA": [ { "steamid64": "7656…" }, { "guest": "Вася", "rating": 700 } ],
    "teamB": [ … 5 человек … ],
    "savedAt": "2026-10-31T16:41:00Z"
  }
}
```

- Игрок из списка хранится только как `steamid64`: имя, аватар и рейтинг MatchDay берёт из
  `stats.json` на момент показа (так актуально и не раздувает файл). Гость хранится как имя
  и рейтинг «на глаз» (1–1500), как в «Выборе составов».
- В каждой команде ровно 5 игроков, всего 10, без повторов. Любая из частей (`maps` или
  `teams`) может отсутствовать: пока не закреплена, на MatchDay показывается «пока не
  определено».
- `sessionDate` — календарная дата без времени (`YYYY-MM-DD`), может быть `null`, если
  владелец дату не указал (заголовок тогда просто «MatchDay»). Дата одна на весь MatchDay:
  любая из двух команд может её задать, и **последняя указанная дата заменяет прежнюю для
  всего MatchDay** (перенесли сессию — достаточно написать новую дату в любой команде).
  Команда без даты оставляет сохранённую дату как есть. Это мой выбор; бот в ответе всегда
  называет текущую дату сессии, чтобы опечатку было видно сразу.
- Файл лежит вне `stats.json`: `build.mjs` его не трогает (при `npm run build` остаётся как
  есть). Нет файла — вкладка MatchDay показывает «Вечер пока не запланирован».

### Сайт (`docs/index.html`)

- Новая вкладка `matchday` с подписью «MatchDay» между «Выбор составов» и «Картами»
  (подпись латиницей, решение владельца). Секция на странице скрывается по `state.tab`, как
  остальные. Вкладка видна всем, без пароля. Сохранённый выбор вкладки в `localStorage`
  (`llstat:selectedTab`) продолжает работать, включая старые значения.
- На экране ≤ 520px шесть вкладок идут двумя рядами по три (сетка из 6 колонок, каждая
  вкладка занимает по 2) — это нужно перенастроить, сейчас раскладка рассчитана на пять.
  Проверить 375px без горизонтального скролла.
- **MatchDay**: заголовок с датой, две карточки команд (аватар, имя, рейтинг игрока из
  `stats.json` или «гость» + рейтинг, средний рейтинг команды), ниже «Маршрут вечера».
  Карты: `bannerUrl` из `stats.json` → `maps[]` (`docs/img/maps/de_*.webp`, все 7 уже
  лежат), название — `displayName`. Плашка — картинка на фоне с тёмным градиентом ради
  читаемости, кружок номера слева на пунктирной линии. Цвета из CSS-переменных сайта.
  Время сохранения мелким служебным текстом. `fetch` `matchday.json` с
  `{ cache: "no-store" }`, как у `stats.json`.
- **Правка варианта состава** («Выбор составов», `renderDraftSection`): выбираете игрока в
  одной команде и игрока в другой, и они меняются местами (способ выбора — на усмотрение
  исполнителя, главное чтобы работал на телефоне). После каждой замены пересчитывается
  средний рейтинг команд. Правки живут только в памяти страницы, не пишутся в
  `localStorage` и не влияют на лимит «2 варианта» (он про генерацию, не про правку).
  Правки относятся к выбранному на экране варианту; кнопка «Сбросить правки» возвращает
  исходное деление. Это мои решения.
- **Порядок карт**: перемешивание Fisher–Yates на `crypto.getRandomValues`, нажимать можно
  сколько угодно раз до отправки боту. Черновик на «Выборе составов» показан тем же
  дизайном дорожки (виден только нажавшему).
- Кнопки «Копировать команду» + «Открыть бота» (t.me-ссылка на `@cs2_stats_tracking_bot`):
  Telegram не умеет подставлять текст в чат с ботом по ссылке, поэтому владелец вставляет
  команду в чат вручную.

### Бот (`bot/src/`)

- Две новые команды: `/maps [дата] <7 ключей>` и `/teams [дата] <команды>`. Разбор и проверка
  — в новом чистом модуле (по образцу `links.mjs`), с тестами.
- `/maps`: ровно 7 разных ключей из пула (с `de_` и без, любой регистр).
- `/teams`: две команды по 5 человек, без повторов; игроки из списка по `steamid64`, гости
  по имени (до 40 символов) и рейтингу 1–1500. Точный формат строки выбирает исполнитель,
  требования: строка копируется одной вставкой, переживает пробелы, запятые и кириллицу в
  имени гостя, и человек может хотя бы приблизительно прочитать, кто в какой команде.
- Дата необязательна (общая для обеих команд, см. «Данные»), формат строго `ДД.ММ.ГГГГ`, переводится в `YYYY-MM-DD` (сегодня по
  Москве); сегодняшняя и будущие допустимы, прошедшие и несуществующие (30.02.2026)
  отклоняются с подсказкой формата.
- Проверка Telegram ID и секретного заголовка — как у остального бота. Токен
  `GITHUB_TOKEN_DISPATCH` уже умеет Actions: Read and write, новых секретов не нужно.
- Ответ в Telegram после приёма команды — «Принял, закрепляю», итог придёт из workflow.

### Workflow `.github/workflows/set-matchday.yml`

- Один workflow на обе команды: входы `kind` (`maps` или `teams`), `payload` (разобранные
  данные команды), `session_date` (`YYYY-MM-DD` или пусто: тогда прежняя дата остаётся). Повторно проверяет данные
  (ровно 7 карт из пула; 2×5 игроков, без повторов; формат даты), не доверяя воркеру слепо.
- Обновляет свою часть `docs/data/matchday.json` (`maps` или `teams`) и, если пришла дата,
  общий `sessionDate`; вторую часть не трогает; ставит `savedAt` текущим UTC; коммитит от `github-actions[bot]`; просит
  сборку Pages (`POST /pages/builds`, как в `update-stats.yml`); сообщает результат в
  Telegram теми же секретами (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`).
- Своя concurrency-группа (две команды подряд не должны писать файл одновременно) и
  `git pull --rebase` перед пушем, чтобы не конфликтовать с коммитами бота статистики.

## Ограничения и риски

- Сайт обновляется через 1–2 минуты после команды боту (Pages), не мгновенно.
- `git push` с компьютера владельца рядом с коммитами бота: решается `git pull --rebase`.
- Дата общая: опечатка в дате второй команды заменит верную дату; бот в ответе называет
  текущую дату сессии, чтобы это было видно сразу.
- Состав игрока по `steamid64`: если игрок пропадёт из `stats.json`, MatchDay покажет его
  как «неизвестный игрок» вместо падения.
