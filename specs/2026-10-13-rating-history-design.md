# История рейтинга — дизайн

Дата: 2026-10-13. Подпроект 2 из 4 (архив сессий ✅ → **история рейтинга** → рекорды → «Итоги вечера»).
Решения по ходу обсуждения с пользователем; `specs/` лежит вне `docs/`, чтобы не публиковаться на Pages.

## Цель

Показать, как менялся рейтинг «за всё время» от сессии к сессии, и дать сравнить нескольких игроков на одном графике: кто растёт, кто падает, кто кого обгоняет.

## Принятые решения

- Место: отдельный блок под таблицей на вкладке «За всё время» (не разворот строки и не отдельная вкладка).
- Ось X — **сессии** (одна точка на игровой вечер), не карты: график не превращается в шум при росте числа карт.
- Пропущенные сессии: **ровная линия** (рейтинг не менялся, пока игрок не играл); до первой сыгранной сессии линии нет; маркеры только в сессиях, где игрок играл.

## Данные (`scripts/build.mjs` → `docs/data/stats.json`)

Новое поле верхнего уровня, остальные поля не меняются:

```
ratingHistory: {
  sessions: [{ id, firstPlayedAt }, …],            // от старой к новой
  players:  { "<steamid64>": [520, 520, 548, …] }  // рейтинг после каждой сессии
}
```

- Длина массива игрока равна числу сессий; порядок совпадает с `sessions`.
- В сессии, где игрок играл, значение — округлённый рейтинг «за всё время» после его последней карты этой сессии (из `history`, которую уже возвращает `computeAllTimeRating`).
- В сессии, где игрок не играл, значение повторяет предыдущее.
- До первой сыгранной игроком сессии — `null`.
- Включены все игроки из `allTime.players` (и неквалифицированные).
- Логика — отдельная чистая функция `scripts/lib/ratingHistory.mjs` (юнит-тесты), `build.mjs` лишь вызывает её.
- Размер: порядка 19 игроков × число сессий — пренебрежимо мал.

## Страница (`docs/index.html`)

- Блок «Динамика рейтинга» под таблицей, виден только на вкладке «За всё время».
- Над графиком — список игроков чипами: выбранные окрашены цветом своей линии. По умолчанию выбраны топ-3 по текущему рейтингу среди квалифицированных (`isQualified`). Максимум 6 одновременно; при попытке выбрать седьмого — подсказка «максимум 6».
- График — встроенный SVG на ванильном JS, без библиотек. X: сессии, подписи «ДД.ММ»; Y: рейтинг с запасом по краям. Тонкая сплошная линия на уровне 500 («средний игрок»; по правилам dataviz пунктир зарезервирован под данные). Маркеры только в сессиях, где игрок играл (кто играл, берётся из `sessions[].players` — формат `ratingHistory` не расширяется). Под графиком — сворачиваемая «Таблица значений» (доступность).
- Наведение мыши/тап: вертикальная направляющая и подсказка — дата сессии и значения выбранных игроков.
- Телефон (375px): график на всю ширину без горизонтального скролла, подписи оси X разрежаются.
- Цвета линий — из проверенной палитры навыка `dataviz`, подобранной под тёмную тему сайта; остальные цвета — только CSS-переменные сайта. При реализации сначала загружается навык `dataviz`.
- Выбор игроков хранится в памяти страницы (после перезагрузки снова топ-3).

## Крайние случаи

- Одна сессия в данных: точки без линии, без ошибок.
- Игрок с одной сыгранной сессией: одна точка.
- Ни одного выбранного игрока: пустой график и подсказка «Выберите игроков».
- В данных нет `ratingHistory` (старый файл): блок не показывается, без ошибок.

## Проверка

- Юнит-тесты `ratingHistory`: пропущенные сессии продолжают значение, `null` до первой сыгранной, порядок сессий, игрок только в последней сессии, игрок только в первой, пустой список сессий.
- Браузер (Edge через Playwright), 1280px и 375px: выбор и снятие игроков, лимит 6, подсказка, нет горизонтального скролла и ошибок в консоли; вкладки «Сессии», «Карты», «Выбор составов» не сломаны.
- `npm test` остаётся зелёным (на момент спеки — 65 тестов).
- `npm run build` пересобирает `stats.json`; коммитит и пушит пользователь.

## Вне рамок

Сглаживание, переключатель «по сессиям/по картам», хранение выбора игроков между перезагрузками, график для вкладок «Сессии» и «Карты» — не делаем (YAGNI), при необходимости отдельными задачами.
