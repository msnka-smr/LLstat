# Telegram-бот для обновления статистики — дизайн

Дата: 2026-10-19. `specs/` лежит вне `docs/`, чтобы не публиковаться на Pages.
Решения по ходу обсуждения с пользователем.

## Цель

Пользователь присылает боту в личный чат Telegram ссылки на лобби cybershoke, после чего автоматически запускается обновление статистики (то же, что кнопка «Обновить статистику» в GitHub Actions). Бот сообщает о начале и о результате.

## Принятые решения

- Ссылки присылает только владелец проекта, бот работает в личном чате. Все остальные отправители игнорируются (проверка по Telegram ID).
- Бот не считает и не хранит статистику. Он только принимает ссылки и запускает существующий workflow `.github/workflows/update-stats.yml` через `workflow_dispatch`. Логика сбора и сборки остаётся в `scripts/update.mjs` и не дублируется.
- Хостинг — Cloudflare Worker (бесплатный план, без своего сервера). Telegram доставляет сообщения на адрес воркера через webhook.
- О результате пользователя оповещает сам workflow последним шагом, а не воркер: сборка идёт минуты, воркер столько ждать не может, а опрос статуса усложнил бы схему.

## Схема

```
Вы → Telegram → Cloudflare Worker → GitHub API (workflow_dispatch) → update-stats.yml
                                                                        ↓
Вы ← Telegram ←────────────── последний шаг workflow: «готово / ошибка»
```

## Компоненты

### `bot/src/worker.mjs` — Cloudflare Worker

Один обработчик `fetch` для `POST` от Telegram:

1. Проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` на равенство секрету `WEBHOOK_SECRET`. Не совпал — `403`.
2. Берёт `message.text`. Если `message.chat.id` не равен `ALLOWED_CHAT_ID` — отвечает `200` и ничего не делает (Telegram иначе будет повторять доставку).
3. Вытаскивает ссылки `cybershoke.net/match/<id>` из текста (`extractMatchLinks`). Дубликаты по id отбрасываются.
4. Нет ссылок — отвечает подсказкой о формате.
5. Есть ссылки — `POST /repos/msnka-smr/LLstat/actions/workflows/update-stats.yml/dispatches` с `inputs.links` (ссылки через пробел) и токеном `GITHUB_TOKEN_DISPATCH`. Успех (`204`) — отвечает «Принял N матчей, обновляю»; ошибка GitHub — отвечает текстом ошибки.

Обработка `scripts/lib/parse-ids.mjs` на стороне workflow не меняется: `collect.mjs` сам вытаскивает id из любого токена, воркер проверяет только наличие ссылок.

### `bot/src/links.mjs` — разбор ссылок

Чистая функция `extractMatchLinks(text) → string[]`: канонические URL `https://cybershoke.net/match/<id>`, без дубликатов, в порядке появления. Отдельный модуль, чтобы тестироваться без воркера.

### `bot/wrangler.toml`, `bot/package.json`

Конфигурация деплоя (`wrangler deploy`), имя воркера, переменные без секретов. Секреты (`BOT_TOKEN`, `WEBHOOK_SECRET`, `GITHUB_TOKEN_DISPATCH`, `ALLOWED_CHAT_ID`) задаются командой `wrangler secret put` и в репозиторий не попадают.

### Изменение `.github/workflows/update-stats.yml`

Новый последний шаг `if: always()`, отправляет сообщение через Telegram Bot API (`sendMessage`) с использованием секретов репозитория `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`:

- успех — «Готово: добавлено N матчей» (N считается по количеству новых файлов в `data/matches` относительно начала запуска) или «Новых матчей нет»;
- ошибка — «Ошибка обновления» и ссылка на запуск в Actions.

Если секреты не заданы, шаг пропускается и не роняет workflow (кнопка в GitHub продолжает работать без бота).

## Безопасность

- Токен GitHub — fine-grained, только репозиторий `LLstat`, право Actions: Read and write. Хранится в секретах воркера, не в коде.
- Адрес воркера защищён секретным заголовком Telegram и белым списком по Telegram ID.
- Токен бота и токены GitHub не передаются в чат и не коммитятся (`bot/.dev.vars` добавляется в `.gitignore`).

## Обработка ошибок

- Нет ссылок в сообщении — подсказка, workflow не запускается.
- Очередь запусков. GitHub держит в группе `concurrency` только один ожидающий запуск: новый вытесняет ожидающего, и тот молча отменяется. Поэтому перед запуском воркер смотрит список запусков workflow: если уже есть два активных (идёт один, ждёт второй; запуски старше 30 минут не считаются), он не запускает третий, а просит дождаться сообщения «Готово» и прислать ссылки ещё раз. Не удалось получить список — запускаем как обычно.
- Сообщение «новых матчей не добавлено» не называет единственную причину: матч мог быть уже учтён, ещё не завершён или чужого состава; в сообщении есть ссылка на лог.
- GitHub API вернул не `204` — пользователь получает код и короткое тело ответа.
- Сбой workflow (в том числе Cloudflare не пускает с серверов GitHub, см. шаг «Проверка связи» в workflow) — сообщение «Ошибка» от последнего шага.
- Повторная отправка тех же ссылок безопасна: `collect.mjs` не дублирует уже собранные матчи.

## Открытый риск: деплой Pages после коммита бота

Не проверено, запускает ли коммит, сделанный `github-actions[bot]` через `GITHUB_TOKEN`, workflow `pages-build-deployment` (см. память проекта «Actions→Pages check»). После появления бота это критичный путь. Проверка — первый сквозной тест: прислать боту ссылку на новый матч и убедиться, что после коммита бота появился запуск `pages-build-deployment`. Если не появился — добавить в workflow явный шаг деплоя или запуск деплоя; это отдельная правка вне объёма бота, но её нужно сделать до того, как считать фичу готовой.

## Тесты

- `test/bot-links.test.mjs`: `extractMatchLinks` — одна ссылка, несколько в одном сообщении, ссылки с хвостом и без `https://`, дубликаты, текст без ссылок.
- `test/bot-worker.test.mjs`: обработчик с подменённым `fetch` — неверный секретный заголовок, чужой chat id, нет ссылок, успешный запуск (проверка тела запроса к GitHub), ошибка GitHub.
- Шаг оповещения в workflow проверяется вручную сквозным запуском.

## Вне объёма

- Команды вроде `/status`, `/undo`.
- Несколько получателей и групповые чаты.
- Собственная логика сбора статистики в воркере.
- Правки сайта (`docs/`).

## Что нужно сделать пользователю

1. Создать бота через @BotFather (`/newbot`), получить токен.
2. Узнать свой Telegram ID (@userinfobot).
3. Завести бесплатный аккаунт Cloudflare, один раз выполнить `npx wrangler login`.
4. Создать fine-grained токен GitHub (репозиторий `LLstat`, Actions: Read and write).
5. Добавить секреты репозитория `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
6. Ввести секреты воркера командами `wrangler secret put` в своём терминале.
7. Зарегистрировать webhook (`setWebhook` с `secret_token`), команда будет в README бота.
